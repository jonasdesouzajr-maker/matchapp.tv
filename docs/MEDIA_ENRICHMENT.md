# MatchApp media enrichment

## Scope

This enhancement is intentionally additive. It does **not** change matching, quotas, billing, authentication, `CONTENT_CATALOG`, Match Together, or the Kids allowlist.

### Data flow

1. `tools/scrape-catalog.js` reads the existing MatchApp catalog and Kids library.
2. Movie/TV identities are matched exactly against TMDB using title + type + compatible year.
3. TMDB supplies posters, backdrops, overview, genres, ratings, official YouTube trailers/teasers and regional watch-provider data.
4. Music/podcast/audiobook entries may use the public iTunes Search API for artwork and short audio previews.
5. Rows are upserted into the existing `public.catalog_media_metadata` table.
6. `/media-enrichment.js` reads that table only as an enrichment/cache layer for titles already rendered by MatchApp.

Trending TMDB rows are stored with `is_catalog_title=false`; they are useful for editorial/SEO analysis but cannot enter recommendations merely because they are trending.

## Secrets

GitHub Actions needs `SUPABASE_SERVICE_ROLE_KEY`. Keep it in **Settings → Secrets and variables → Actions** only.

TMDB auth is resolved in this order:

1. `TMDB_READ_TOKEN` GitHub Actions secret
2. `TMDB_BEARER_TOKEN` environment secret
3. Supabase `runtime_secrets.TMDB_BEARER_TOKEN` (read server-side using service role)
4. `TMDB_API_KEY` as a legacy fallback

No service-role key or TMDB credential is shipped to the browser.

## Existing Supabase model

`catalog_media_metadata` already contains the required fields and has RLS enabled. Public read access is limited to its catalog metadata policy; writes in the refresh job use service-role. Existing indexes cover normalized title, TMDB ID and trending rank, so no schema migration is needed for this release.

Important fields:

- identity: `source_key`, `title`, `normalized_title`, `year`, `media_kind`, `tmdb_id`, `source`
- authority flags: `is_catalog_title`, `is_trending`, `trending_rank`, `kids_approved`, `kids_age_bands`
- images: `poster_url`, `poster_large_url`, `poster_original_url`, `backdrop_url`
- metadata: `overview`, `genres`, `runtime_minutes`, `content_rating`, `vote_average`, `original_language`
- preview: `preview_kind`, `preview_provider`, `preview_url`, `preview_embed_url`
- availability: `availability` JSON by country

## Images

The existing artwork chain remains first. `media-enrichment.js` listens for failed/empty poster-like images only. Recovery order:

1. enriched Supabase poster (`w780`, then `w500`, then original)
2. a deterministic local SVG data URI containing the title/year and MatchApp branding

Logos, avatars and icons are excluded. The fallback is a data URI, so it cannot itself create another network failure.

## Preview players

- Movie/TV: only validated `youtube-nocookie.com/embed/...` URLs generated by the server-side refresh are embedded.
- Music/audio: only HTTPS Apple/mzstatic preview URLs are placed in the `<audio>` player.
- Missing preview: player remains hidden.
- Kids: the preview is rendered only when the metadata row has `kids_approved=true`. That value is derived from the existing `kids/kids.js` allowlist, never inferred from TMDB.
- Trailer names containing obvious restricted/red-band terms are rejected for Kids during refresh as defense in depth.

## Daily GitHub Action

`.github/workflows/scraper.yml` runs daily and can also be started manually. It writes metadata to Supabase, runs the full test suite and site/search audit, and uploads the refresh log as a 14-day workflow artifact. Its final JSON metrics line reports attempted/enriched/skipped/errors/posters/previews/provider counts.

The pre-existing weekly static availability workflow remains unchanged. This daily job enriches Supabase; it does not rewrite the static SEO pages.

## Staging / release procedure

1. Work on `staging/media-enrichment-20260917`.
2. Open the PR to trigger the normal validation workflow.
3. Confirm `npm test` and `npm run audit:site` pass.
4. Run a small manual refresh with `CATALOG_REFRESH_LIMIT=10` after confirming the GitHub service-role secret is present.
5. Inspect the inserted rows in Supabase and test regular + Kids result cards.
6. Increase to a full manual refresh.
7. Merge only after these checks pass. Scheduled execution starts only after the workflow exists on the default branch.

## Attribution / licensing

TMDB watch-provider data is supplied through TMDB's JustWatch partnership and requires JustWatch attribution. Keep attribution on surfaces that present provider data. MatchApp already identifies TMDB as the metadata/artwork source in its credits/about material; verify the commercial TMDB license appropriate to MatchApp's monetized use.

## Measurement

At deployment, create a Search Console/GA4 annotation and compare at least 14 days before vs. after on:

- organic clicks, impressions, CTR, average position
- landing-page engaged sessions and engagement rate
- match completion / result interaction events
- preview starts (recommended event: `preview_start`, dimensions `media_kind`, `preview_provider`, `kids_mode`)
- Watch Later / outbound watch clicks following a preview

GitHub Action metrics cover refresh health. Supabase query latency and row counts should be monitored through Supabase logs/advisors. Cloudflare should monitor cache/error/request behavior for public site traffic; the current ChatGPT connection has no Cloudflare connector, so Cloudflare-log validation remains an account-side operational check rather than something performed by this branch.
